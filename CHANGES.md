# CHANGES.md — reconstruction notes

This project was rebuilt from a flat file dump (original directory structure
lost). No uploaded file's business logic was modified. Below is the complete
list of recreated files and the minimal changes made to uploaded files.

## Recreated files (were NOT in the dump — inferred from importers)

### Server
- `api/queries/connection.ts` — `getDb()`: lazy mysql2 pool + Drizzle handle,
  `DATABASE_URL` from `.env` via dotenv. Imported by admin/telephony/
  verification routers, simulator, seed and tests.
- `api/lib/env.ts` — typed env module; `env.isProduction` gates the production
  boot path in `api/boot.ts`.
- `api/lib/cookies.ts` — `getSessionCookieOptions(headers)`: SameSite/Secure
  derived from `x-forwarded-proto`. Used by `api/auth-router.ts`.

  explicit Content-Type map (`.wav` → `audio/wav`, required by Twilio) and SPA
  fallback to `index.html`.
- `api/kimi/auth.ts` — `createOAuthCallbackHandler()` +
  `authenticateRequest(headers)`. Stateless HMAC-signed session JWT (jose) in
  the `kimi_sid` cookie (`Session` in `contracts/constants.ts`); users upserted
  by `unionId`. ASSUMPTION (documented in-file): the platform exposes
  `POST {KIMI_AUTH_URL}/api/oauth/token` and `GET …/api/oauth/userinfo`;
  Login.tsx builds the matching authorize URL.

## Changes to uploaded files
1. `package.json` scripts only — `check`, `build`, `test` now invoke
   `node node_modules/<pkg>/<bin>` explicitly instead of relying on
   `node_modules/.bin` shims. Reason: the target filesystem
   (/mnt/agents/output, FUSE portal) does not support symlinks or exec bits,
   so npm's `.bin` links can neither be created nor executed there, and
   unqualified commands resolve to incompatible global tool versions
   (tsc 7 rejects `baseUrl`; global vite 8/rolldown mis-minifies
   tw-animate-css). The explicit form behaves identically on normal
   filesystems. No other field of `package.json` was touched; dependency
   versions are exactly the uploaded ones (lockfile untouched).

## Environment notes (not repo changes)
- `npm ci` was validated against the uploaded `package-lock.json` (636 pkgs).
  On the portal FS it must run with `--no-bin-links` (no symlink support);
  this repo ships a ready `node_modules` so install is not needed to run the
  commands below.
- On this sandbox, native binaries cannot execute under /mnt/agents
  (no exec bit). `npm run build` / `npm test` were run with
  `ESBUILD_BINARY_PATH=/tmp/nativebin/esbuild` (an exec-capable copy of
  `@esbuild/linux-x64`). On any normal filesystem this is unnecessary.
- `.env` (gitignored normally) is included for local reproducibility:
  `DATABASE_URL=mysql://root@127.0.0.1:3306/cloudtalk` against a local
  MariaDB 10.11 started from extracted Debian packages
  (`/tmp/mdb-root`, datadir `/tmp/mdb-data`, socket `/tmp/mdb-run/mysql.sock`).
  Schema was applied from `db/migrations/0000_*.sql` (generated by
  `drizzle-kit generate`; the literal `serial AUTO_INCREMENT` token sequence
  drizzle-kit emits was rewritten to `bigint unsigned AUTO_INCREMENT` because
  MariaDB rejects the former — a migration-file-only compatibility fix, the
  drizzle schema itself is unchanged). The database must use utf8mb4:
  `CREATE DATABASE cloudtalk CHARACTER SET utf8mb4`.
- `api/verification.test.ts` requires a live MySQL-compatible database (by
  design — it says "runs against the real dev database").
